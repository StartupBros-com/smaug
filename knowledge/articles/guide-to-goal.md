This guide explains how to use Codex's /goal mode for work that may run for hours or days. Goal mode repeatedly checks whether its stated outcome has been achieved, so the quality of the goal, the available measurements, and the fidelity of the working environment determine whether extended autonomous work converges on a useful result.

The author recommends beginning with concise, verifiable exit criteria, ideally with a concrete target. Operators should add pointers when they know where a problem lies, provide tools that make progress observable, and ensure the agent can test against an environment that resembles production. The guide also cautions that image-driven objectives need constraints beyond pixel matching, because visual diffing alone can reward shortcuts.

## Key Takeaways

- Define clear completion criteria so the agent can distinguish a finished outcome from partial progress.
- Give the agent measurements, test environments, and focused starting guidance instead of relying on a broad aspiration.
- Track longer runs with meaningful commits, draft pull requests, status artifacts, or side chats rather than waiting for the final result.
- Review and clean up the accumulated solution after the goal is reached, since iterative attempts can leave unnecessary changes behind.
