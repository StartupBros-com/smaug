This guide describes a live Obsidian dashboard as a read layer rather than another place to store information. It uses consistent YAML properties and the Dataview plugin to assemble today’s priorities, active projects, imminent deadlines, client health, open loops, and revenue from notes that remain their own system of record. It then adds Claude Code via Filesystem MCP to create a concise morning briefing and update task and project properties from structured entries in daily notes.

## Key Takeaways

- A dashboard stays current by querying structured source notes; it should not duplicate their contents.
- Consistent property names, folders, ISO-formatted dates, and note types are prerequisites for dependable Dataview results.
- Six focused views—priorities, projects, next-seven-day deadlines, client health, open loops, and revenue—turn a vault into a daily operational overview.
- The `OPEN:` convention carries informal unfinished work forward from daily notes without creating a separate tracking system.
- Claude Code can synthesize the live dashboard into an under-300-word morning briefing and apply `DONE:` and `UPDATE:` instructions back to the vault.
