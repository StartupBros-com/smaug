This analysis argues that AI memory should no longer be valued solely as a cyclical commodity business. It traces a progression from standard HBM, through logic-process base dies and customer-specific HBM (cHBM), toward memory-on-logic architectures that stack memory directly over a compute die. Each step embeds more customer-specific circuitry into the memory product, making it harder to substitute one supplier's part for another and potentially shifting memory suppliers toward the role of custom-silicon partners.

The article explains that cHBM is the nearer-term commercialization path because it moves customer interfaces, controllers, and other logic into an HBM base die without immediately requiring a fully stacked compute-and-memory package. Memory-on-logic promises much denser, shorter interconnects and lower data-movement energy, but faces serious thermal and yield challenges when temperature-sensitive DRAM sits above a high-power compute die. Qualcomm's proposed HBC architecture is presented as one possible alternative: pairing a dedicated lower-power accelerator with LPDDR to stay within thermal and packaging constraints.

## Key Takeaways

- Logic-process HBM base dies enable more bandwidth and power-management functionality than DRAM-process base dies, and create room for customer-specific logic.
- cHBM could make memory products dedicated to individual accelerator customers, reducing interchangeability and increasing supplier-customer design collaboration.
- Memory-on-logic eliminates the conventional interposer connection by stacking memory directly on compute logic, potentially improving bandwidth density and energy efficiency.
- Heat dissipation, DRAM temperature sensitivity, yield, and packaging cost are the central constraints on broad memory-on-logic adoption.
- The investment thesis is that custom memory designs could change memory makers' revenue and margin profiles before those changes are visible in conventional cyclicality-based valuation models.
