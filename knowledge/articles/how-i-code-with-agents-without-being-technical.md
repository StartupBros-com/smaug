Ben Tossell explains how he has used coding agents from the terminal to ship personal tools, product experiments, custom CLIs, a social feed, a trading tracker, and an AI-directed video system without first becoming a conventional programmer. He treats the work as an iterative operating practice: provide context, challenge plans, watch execution, run the product, give feedback, and convert recurring problems into reusable instructions and commands.

His argument is that agent-assisted building creates a new kind of technical fluency. Instead of memorizing syntax before attempting projects, builders can learn systems, testing, deployment, and engineering trade-offs through the gaps that emerge while shipping. This depends on active oversight rather than passive prompting: he reads agent output, asks questions about failures, tests what is built, maintains `agents.md` guidance, and uses pull requests and reviews to close knowledge gaps.

## Key Takeaways

- Use a terminal-based agent workflow to keep execution visible and make command-line tools reusable across projects.
- Begin with an idea or pain point, supply context and documentation, interrogate the plan, then test and iterate on the implementation.
- Treat an `agents.md` file and reusable slash commands as portable operating instructions that reduce repeated setup and encode lessons from prior work.
- Build small, disposable experiments to accelerate feedback and learn systems concepts from real constraints rather than isolated tutorials.
- Prefer understanding how to direct, evaluate, and improve an agent over pursuing a complex universal harness; the right workflow is the one that helps a builder make progress reliably.
