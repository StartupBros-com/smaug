Shann Holmberg's agency field guide for turning marketers into "marketing engineers" by stacking four layers that are usually sold as separate fads: context, harness, loop, and graph. Models and agents sit next to the stack, not in it. Context is what lands in the window on this call. The harness is the machine around the model (skills, tools, connectors, memory, permissions, routing, sign-offs). A loop is draft → score against a rubric you wrote → retry until it passes or hits the budget. A graph is the fixed multi-stage campaign map — nodes, routes, checkpoints, and gates nothing skips. Each outer layer decides what the one inside it can do, so by the time the model writes a word its tools, route, and retry budget are already set. Every example comes from systems at Lunar Strategy and Espressio.

**Loop engineering** is designing that retry system so you are not typing the next instruction. Shape it with three questions: how many agents (one self-loop vs a fleet with an orchestrator), how much room (open/exploratory vs closed/bounded), and what starts and checks the run (agent loop, verification loop, event-driven trigger, self-improvement over traces). Marketing already has the cycles — content, SEO, campaign, or a fleet of those — the engineering is making them run and check themselves. The verification loop is the slop filter: write the rubric first (truth, proof, specificity, voice, positioning, offer fit), score 0–1, send misses back with the failing line named. Loop only on evidence the agent cannot fake (indexed URL, HTTP 200, rubric clear). A loop without a done state spends its budget on paths you never asked for. LOOPER by KSimback is the design pass before `/goal` burns tokens.

**Graph engineering** is drawing the whole campaign before anything runs. A loop owns one stage (landing page until the rubric clears); a graph is the path every cohort walks. Four pieces: nodes (research, plan, landing, emails, launch — some are themselves loops), routes (allowed handoffs), checkpoints (forward or back), gates (cannot skip — rubric plus human sign-off). The worked map is idea → ideation → research → plan → your sign-off → fan-out build → join → pre-launch sign-off → launch → results. Asset loops can clear every writing rubric and the campaign still miss; put a results node at the end that only live numbers (opens, CPL, signups) can pass, and route a miss back to research or the plan, not the subject line. Lock brand voice, forbidden claims, routes, and both sign-offs; swap models, tools, research depth, and individual rubric lines inside a node. Use a graph for weekly/monthly repeat work; use a lone loop when you do not know the path yet.

**Harness engineering** is the machine under each stage. Seven pieces for marketing: skills/plugins/bundles, tools, connectors (CRM, CMS, Search Console, ads, email, analytics), sandboxed execution, memory between runs, control (timeouts, budgets, routing, sign-offs), and observability. A model alone only generates text. In an agency the harness is the org chart: one specialist per vertical with a `soul.md`, a skill pack, its own sandbox and credentials, and isolated pods so client data never crosses. Reach is a harness decision — the content agent can draft and queue, not post, send, edit the CRM, or move spend above the cap.

**Context engineering** is choosing which tokens enter the window. The company brain is where you pull from: a knowledge layer (calls, docs, brand, voice) plus a data warehouse (metrics, exports), indexed together so one query can return a brand rule and a campaign number. Internal context is only yours (brain + a voice note cleaned into a brief); external is competitors, SERPs, recurring questions. Skills decide which slice of the brain enters this run so the model does not read the wrong pages. Keep the window clear with compaction, note-taking, and sub-agents that return a short result. Context is the layer you build first — tools and harness patterns are public; your data, voice, and taste are not.

Build order: (1) company brain, (2) harness, (3) one repeated loop with a done state, (4) graph routes and evals that file misses back into the brain. The four decisions that matter: what the model reads, what it can reach, how it retries, and the order the work runs in.

## Key Takeaways

- The four layers stack; treating prompt/context/harness/loop/graph as standalone "engineerings" is the trap
- Own the path (graph + gates); let agents own the work on the path
- Write the rubric and the done state before the first token; loop only on evidence the agent cannot fake
- Results nodes beat critic loops — a perfect landing-page score can still produce zero signups
- Build the company brain first; public tools do not differentiate, proprietary context does
- Agency harness = org chart: narrow specialists, `soul.md`, isolated client pods, sign-off before send/spend
